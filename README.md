## Формы и ограничения предпросмотра

**Каталог.** Четыре кнопки с атрибутами `data-catalog` и `data-catalog-request` открывают одну форму «Получите каталог проектов». Обязательны телефон и согласие на обработку персональных данных. Имя, способ получения и дополнительный контакт необязательны. Способы получения: Почта, Макс, Телеграм; по умолчанию «Не выбрано». Дополнительное поле появляется после выбора способа.

**Заказ звонка.** Кнопка в шапке с атрибутом `data-callback` открывает форму «Есть вопрос? Закажите звонок специалиста!» В ней одно поле телефона, кнопка «Заказать звонок» и согласие под ней, оформленное как в каталоге.

**Задать вопрос.** Две второстепенные контурные кнопки расположены на первом экране и в нижнем блоке под кнопкой каталога. Они открывают одну форму «Задайте вопрос специалисту»: обязательный телефон, необязательные имя и вопрос, согласие. На всех экранах «Задать вопрос» стоит под «Получить каталог» и совпадает с ней по ширине и высоте; текст второстепенной кнопки выровнен по левому краю с текстом основной. Оформление, текст и стрелка «Получить каталог» сохранены. Приём вопросов пока не подключён, как и отправка остальных форм.

Во всех трёх формах чекбокс согласия изначально пуст. Ссылка на правила обработки персональных данных открывается в новой вкладке. Проверяются телефон и согласие; в каталоге также проверяется заполненный дополнительный контакт. Диалоги закрываются крестиком, Escape и нажатием вне окна; после закрытия восстанавливаются прокрутка и фокус на открывшей кнопке.

**Отправка заявок, хранение контактов, CRM и автоматическая выдача PDF не подключены.** После успешной проверки все три формы показывают: «Форма заполнена. В этой версии заявки не отправляются.» Не заменять это сообщение подтверждением отправки до подключения и проверки приёма заявок. Телефон и почта в контактах работают через `tel:` и `mailto:`.

Предпросмотр публичен по ссылке. В HTML стоит `noindex,nofollow,noimageindex`, но это не ограничение доступа. Перед рекламным запуском нужно подключить обработку заявок и каталог, проверить актуальность цен, условий и документов, затем отдельно решить вопрос индексации.

## Видео и правила дальнейших правок

В `assets/cinema/videos.json` у каждой записи есть `title`, `poster` и `embedUrl`. Разрешены HTTPS-ссылки на `/video_ext.php` доменов `vk.ru`, `vk.com`, `vkvideo.ru`. Плеер создаётся только после нажатия; до этого используются локальные обложки.

После загрузки JSON скрипт создаёт карточки по его записям, поэтому количество видео определяется JSON. В `index.html` также есть резервные карточки на случай ошибки загрузки данных. При изменении списка видео синхронизировать JSON и резервный HTML, чтобы оба варианта показывали актуальные материалы.

Основные кнопки используют общий `.cta`, заголовки разделов — `.section-title`. Сохранять общие размеры, вертикали контейнеров и адаптивность. Диалоги используют общее оформление `.catalog-modal` и `.catalog-form`. Водяные знаки пользователя сохранять при дальнейшей обработке фотографий. Исходные фото и согласованные материалы не перезаписывать обработанными версиями.

Страницы сравнения ипотеки `mortgage-options.html` и `mortgage-options-right.html` удалены из текущей версии. Их исходники доступны в истории Git; утверждённый ипотечный блок остаётся в основном лендинге. По решению пользователя сохранены `variants/01.html`, `variants/02.html`, `variants/03.html`; страница `research.html` также остаётся.

## Локальный просмотр и проверка

Из корня актуального репозитория:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8080/. Сервер нужен в том числе для загрузки `videos.json`; открытие через `file://` не заменяет проверку сайта.

Перед отправкой изменений:

```sh
git status --short
git diff --check
node --check assets/cinema.js
node --check assets/catalog-form.js
node --check assets/callback-form.js
node --check assets/question-form.js
```

Для изменений интерфейса проверить затронутые блоки на компьютере и телефоне, отсутствие горизонтальной прокрутки и ошибок JavaScript. Для форм проверить открытие, обязательные поля, пустой чекбокс согласия, закрытие и восстановление фокуса. Для галерей — навигацию и закрытие просмотра. Проверки из `research/verification-*.json` относятся к указанным в них версиям и не заменяют проверку новых изменений.

При изменении файла с параметром версии в URL подключения обновлять этот параметр в `index.html`; для JSON видео соответствующий параметр находится в `assets/cinema.js`.

## Публикация предпросмотра на GitHub Pages

### Как устроен выкат

Рабочий remote `origin` — `https://github.com/Kastet36/ruspom-preview-2.git`, ветка публикации — `main`. Старые remotes `previous-origin` и `previous-preview` сохранены для истории; в них текущий предпросмотр не публикуется.

В Settings → Pages → Build and deployment выбран **GitHub Actions**. Workflow [Publish site](.github/workflows/pages.yml) запускается при каждом push в `main` (в том числе при изменении README) или вручную через `workflow_dispatch`.

Задание `build` копирует корневые `*.html`, `assets/`, имеющиеся `provided/`, `research/`, `site/`, `variants/`, `dist/`, `licenses/` и `content.json` в `_site/`, добавляет `.nojekyll`, проверяет наличие главных файлов и загружает артефакт через `actions/upload-pages-artifact@v4`. Задание `deploy` после успешного `build` публикует его через `actions/deploy-pages@v4` в окружение `github-pages`. Сборщика приложения нет. В concurrency используется группа `pages` с `cancel-in-progress: false`.

### Порядок публикации

1. Проверить текущую папку, remote, ветку и незакоммиченные изменения:

   ```sh
   pwd
   git remote -v
   git branch --show-current
   git status --short
   ```

2. Выполнить проверки выше, просмотреть `git diff`, добавить только относящиеся к задаче файлы и создать коммит. Например, для правки формы звонка:

   ```sh
   git add index.html assets/cinema.css assets/callback-form.js
   git commit -m "Update callback form"
   ```

   Если менялась документация, добавить соответствующие `README.md` и `CONCEPT.md`.

3. Отправить согласованные изменения в ветку публикации:

   ```sh
   git push origin main
   ```

4. Открыть https://github.com/Kastet36/ruspom-preview-2/actions и найти запуск `Publish site` для отправленного коммита. Через GitHub CLI:

   ```sh
   gh run list --repo Kastet36/ruspom-preview-2 --workflow pages.yml --limit 5
   gh run watch RUN_ID --repo Kastet36/ruspom-preview-2 --exit-status
   ```

   `RUN_ID` заменить на ID запуска нужного коммита. Успешный push ещё не означает завершение публикации: оба задания, `build` и `deploy`, должны завершиться успешно.

5. Открыть https://kastet36.github.io/ruspom-preview-2/ и проверить опубликованные изменения. Публичная ссылка остаётся постоянной, без параметров версии. При старом содержимом обновить страницу с очисткой браузерного кеша и сверить коммит запуска Actions.

### Повторный запуск и ошибки

Для повторной публикации текущего `main` без нового коммита:

```sh
gh workflow run pages.yml --repo Kastet36/ruspom-preview-2 --ref main
```

Если выкат завершился ошибкой, открыть упавшее задание в Actions или получить журнал:

```sh
gh run view RUN_ID --repo Kastet36/ruspom-preview-2 --log-failed
```

Исправить причину и отправить новый коммит либо повторить запуск после устранения внешней ошибки. Для отмены ошибочной опубликованной правки создать `git revert` нужного коммита и отправить его обычным push в `main`; новый запуск восстановит состояние сайта. Не использовать принудительную перезапись истории для отката предпросмотра.


## Запрет индексации предпросмотра

На всех HTML-страницах предпросмотра задан `<meta name="robots" content="noindex,nofollow,noimageindex">`. Это запрещает поисковую индексацию страниц и изображений на них для роботов, поддерживающих эти директивы. Перед загрузкой артефакта workflow запускает `scripts/check-noindex.py _site`: публикация останавливается, если хотя бы у одной HTML-страницы нет этих директив внутри `head`. Новые страницы должны содержать тот же тег.

Обход страниц не блокируется через `robots.txt`, чтобы поисковики могли прочитать `noindex`. Если страницы уже попали в выдачу, исключение произойдёт после повторного обхода. Это не ограничивает доступ к сайту по прямой ссылке. На GitHub Pages настройка относится к HTML-страницам; отдельные URL файлов не получают HTTP-заголовок `X-Robots-Tag`.


Во всех трёх формах убраны видимые пометки «Необязательно». Правила обязательности полей сохранены в логике форм.
